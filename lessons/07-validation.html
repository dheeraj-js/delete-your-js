Lesson 07 / 17 · ✅ :user-invalid

Form errors that wait until you've had a go

Nobody likes a form that shouts "WRONG!" before you've typed anything. We used JS to wait until the user had finished with a field. Now there's a CSS mood for exactly that.

Replaces: blur listeners · "touched" classes · validation JS Uses: required · type="email" · :user-invalid · :user-valid ✅ All modern browsers (Baseline 2023)

1 In plain English

🤔

What are we building?An email box that tells you if it's wrong

Red border and a message if the email is wrong, green if it's right. But only after you've tried.

📝

😓 The old wayA teacher who takes notes

JS watches you. When you leave the box, it writes down "this one was touched", then checks the answer and adds a red or green sticker.

🧑‍🏫

😎 The new wayA polite teacher built into the browser

The browser already knows two things: is the answer valid? and has the user had a go? :user-invalid means "both: wrong, and they've tried".

😡 The problem: plain :invalid is too eager

It's already red and you haven't typed anything!

😊 What we want: wait until the user has tried

The browser tracks whether you've typed something and left the field (or tried to submit). That's exactly what the old JS was doing by hand. ⬇️

🧐 What this code does, step by step

  1. blur is the event for "you just left this box". Then JS adds a touched sticker.
  2. JS asks the browser checkValidity(): "is this a valid email?" (the browser already knows!).
  3. Depending on the answer, JS swaps the is-error / is-ok stickers and shows or hides the message.
  4. While you type, JS re-checks only if the box was touched before, so the red goes away as soon as you fix it.
  5. Notice: the browser already knew the answer. JS was just carrying the message to CSS.

🧐 What this code does, step by step

  1. The HTML does the checking: type="email" = "must look like an email", required = "can't be empty".
  2. :user-invalid is a mood 😊 meaning "wrong, AND the user has typed and left, or tried to submit".
  3. :user-valid is the happy version: correct, after the user has tried.
  4. + means "the element right after". So: "when the box is user-invalid, show the message after it".
  5. No stickers, no listeners. The browser already tracks "touched", and now CSS can see it.

  2. 🚪You leave the box (blur)
  3. 📝JS writes "touched"
  4. ❓JS asks the browser "valid?"
  5. 🏷️JS adds the red sticker

😎 After

  1. ⌨️You type "hello" and leave
  2. 🧑‍🏫Browser: "wrong + tried = :user-invalid"
  3. 🎨CSS turns it red

4 Good to know

🧰

Other free HTML checks: minlength, maxlength, min, max, pattern (your own rule), type="url", type="number".

🔒

Always check on the server too. Browser checks are for being friendly. Anyone can skip them.

🤝

Combine with :has() (next lesson): form:has(:user-invalid) button means "if anything in the form is wrong, dim the submit button".
